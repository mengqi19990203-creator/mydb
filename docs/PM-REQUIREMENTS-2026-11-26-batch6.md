## 0. 本批结论

### 0.1 一句话目标

让 SQL 里的表名和列名可以直接点开；让查询结果可以固定下来跨多次运行对比；让宽结果的列顺序和转置顺手可用；让断线能被发现并安全恢复；让一列数据的质量、统计和分布一眼可见。

### 0.3 推荐实施顺序与理由

**实施顺序：H-01 → H-02 → H-03 → H-04 → H-05。**

| 编号 | 用户价值 | 实现风险 | 价值 × 风险判断 | 排序理由 |
|---|---|---|---|---|
| H-01 | 高 | 低 | 最高性价比 | 纯前端、无存储、复用 G-05 tokenizer；每次写 SQL 都受益，适合作为快速开局 |
| H-02 | 很高 | 中 | 本批最大缺口 | 两个主流竞品都有固定 / 对比；纯前端但涉及结果模型、内存与差异语义，需完整验收 |
| H-03 | 高 | 中 | 高频但需克制 | 列重排每天用；转置是宽表补充；必须处理冻结、隐藏、选区、导出与持久化 |
| H-04 | 高 | 中高 | 价值高但生命周期复杂 | 唯一涉及后端的项；连接 / 事务 / 独立窗口 / 自动重连的竞态必须先设计清楚 |
| H-05 | 中 | 低 | 低风险补全 | 纯前端；与 G-01 / G-03 相邻但职责不同；可最后做，也可在不影响前四项时单独交付 |

- **H-01 最先做**：成本最低、纯前端、无数据库写入、无新依赖；先把「SQL 文本 → 当前 scope 对象 → 现有表标签」的路由打通，后续 H-02 的固定结果与 H-03 的列顺序都不会与它冲突。
- **H-02 第二**：这是当前工作流里最大的能力缺口——查询一重跑，上一次结果就没了；多语句的「结果 1 / 结果 2」只是同一轮运行的切换，不是跨运行固定。先固定再对比，是排障、验证数据修复、对比两次 SQL 的最短路径。
- **H-03 第三**：列重排是「宽表阅读」的直接延伸；转置是单行 / 少行宽记录的补充视图。放在 H-02 之后，因为固定结果也需要列重排与转置，且两者共享列顺序模型。
- **H-04 第四**：价值高，但它是本批唯一需要改 Rust 命令层的项；必须先定义事务、运行中查询、独立查询窗口、SSH 隧道、Redis 选库的边界。即使缩减为「只提示 + 手动重连」，也不影响前四项交付。
- **H-05 最后**：纯前端、低风险，但边际价值低于前四项；放在最后，即使只做查询结果、暂时不做表数据当前页，也能独立交付。

**若只能做一项**：做 **H-02**。它是本批唯一会改变「查询结果生命周期」的能力，也是 DBX / DBeaver / Navicat 都明确提供的差异点；H-01 虽然便宜，但不解决最大的工作流缺口。

**若只能做两项**：做 **H-01 + H-02**。先花半个会话把 H-01 落地（风险最低、立即见效），再进入 H-02；两者没有共享状态冲突，合并交付的感知最强。

### 0.4 竞品研究与差距结论（2026-11-26，第四批）

调研对象与边界：DBX（Apache-2.0，公开文档）、DBeaver（Apache-2.0，公开 wiki / 官方文档）、Navicat（专有，只参考公开产品页 / 帮助文档 / 手册中的功能描述）。只比较用户可见能力与交互，不复制实现与文案。

#### 4.1 DBX（重点参考）

- **结果固定 / 多轮结果**：数据表格文档说明查询结果可以保留多次运行，或固定结果用于比较；固定结果与当前运行结果可以并存。
- **转置视图**：数据表格提供 Transposed View，交换行列，适合单条多字段记录、查看字段类型 / 注释 / 可空性、检查宽值；选择、复制、详情、编辑和导航仍可用，但数据库侧排序 / 筛选仍按原始方向。
- **列布局**：拖动列头重排列顺序，列宽可拖动 / 双击适配，布局按表或查询保存；另支持隐藏列、搜索列、隐藏全 NULL 列。
- **对象导航**：查询编辑器支持 `Ctrl/Cmd+Click` 表名打开数据或定位对象，依赖 SQL 解析与当前元数据；动态 SQL、歧义名称或无 schema 引用可能需要手动确认。
- **粘贴语义**：数据表格的批量粘贴文档明确是粘贴到**新增行**，不是覆盖已有行；覆盖语义只出现在数据传输的「清空目标表再写入」，与网格覆盖不同。
- 来源：<https://dbxio.com/en/docs/data-grid>、<https://dbxio.com/en/docs/query-editor>、<https://github.com/t8y2/dbx/blob/main/docs/content/docs/data-grid.mdx>、<https://github.com/t8y2/dbx/blob/main/docs/content/docs/query-editor.mdx>

#### 4.2 DBeaver（公开 wiki / 官方文档）

- **结果标签固定**：SQL 执行文档说明结果标签可以 Pin，固定后不会被下一次执行覆盖，固定在左侧，未取消固定前不能关闭；多结果可以按标签查看。
- **Record 视图 / 转置**：Data Editor 的 Record 视图交换行列位置，把列显示为行、行收进一个 Value 列，适合列很多、单行阅读；Tab 键或 Layout → Record 可切换。
- **列顺序**：Data Editor 提供列排序 / 顺序子菜单与列显示控制；官方文档对拖拽重排的描述不如 DBX 明确，但「展示顺序可调整、不影响数据库结构」是公开能力。
- **数据对比 / 迁移**：Data Compare 可比较两个结果集、两张表，甚至跨数据库 / RDBMS；Data migration 的 Column mapping 支持源列 → 目标列、目标类型调整、Set to NULL / Constant / Expression 变换，以及 Create / Existing / Recreate / Skip 等映射动作。
- **计算与导出**：Calc 面板对选中单元格计算 Count / Count distinct / Count nulls / Sum / Average / Minimum / Maximum / Median / Mode；数据导出支持 fetched rows / selected rows / selected columns。
- 来源：<https://dbeaver.com/docs/dbeaver/SQL-Execution/>、<https://dbeaver.com/docs/team-edition/26.0/desktop/Data-Editor/>、<https://dbeaver.com/docs/dbeaver/25.0/Data-View-and-Format/>、<https://dbeaver.com/docs/dbeaver/Calc-Panel/>、<https://dbeaver.com/docs/dbeaver/Data-compare/>、<https://dbeaver.com/docs/dbeaver/Data-migration/>、<https://dbeaver.com/docs/dbeaver/26.2/Data-export/>

#### 4.3 Navicat（公开产品页 / 帮助文档 / 手册）

- **固定查询结果**：查询编辑能力包含 Freeze & Compare Result Snapshots；手册说明 Pin 会保留结果标签，重新执行查询不会清除固定结果，固定标签显示 pin 图标并排到标签栏左侧，悬停可看执行时间与查询。
- **Data Profiling**：表数据工具栏提供 Data Profiling，结果分 Column Quality（NULL 比例、离群等）、Column Distribution（值分布直方图）、Column Statistics（类型、最小值、最大值、平均值、标准差、distinct 数、NULL 数）；可按筛选后的记录或前 N 条记录剖析。
- **现有表设计器**：Table Designer 可编辑字段、索引、外键、触发器、选项与注释，保存前有 SQL Preview；这与 mydb 的「结构页增量 ALTER + 新建表设计器」不同。
- **连接保活 / 自动重连**：Navicat 连接属性提供 Keepalive Interval 与断线自动重连选项；公开手册 / 帮助与用户文档广泛描述，官方 PDF 手册可作入口。
- **筛选后导出**：应用 Filter & Sort 后可选择导出当前筛选记录，而不是整表。
- 来源：<https://www.navicat.com/en/products/query-editing>、<https://www.navicat.com/manual/pdf_manual/en/navicat_17/win_manual/navicat_en.pdf>、<https://help.navicat.com/hc/en-us/articles/46711325532697-How-to-use-the-Data-Profiling-feature-to-analyze-data>、<https://help.navicat.com/hc/en-us/articles/217806188-How-do-I-export-filtered-records-after-applying-a-filter-to-a-table-or-collection>、<http://www.navicat.com/manual/pdf_manual/en/mac_manual/MySQL_Database_Object_Management.pdf>

#### 4.4 全量差距表与本批决策

| 能力 | 竞品参考 | mydb 现状（2026-11-26 代码核对） | 现状标注 | 本批决策 |
|---|---|---|---|---|
| SQL 中点击表 / 列打开对象 | DBX `Ctrl/Cmd+Click` | 有补全（`completionTables`）、有 G-05 tokenizer、有全局对象搜索和现有表标签；没有任何「点击 SQL 文本打开表 / 列」的入口 | **完全缺失** | **H-01** |
| 结果固定 / 多次运行对比 | DBX 保留 / 固定结果；DBeaver Pin tab；Navicat Pin | `QueryTab.resultSets` 只保留同一轮多语句的结果，下一次运行即替换；没有固定、命名、对比；结果也不持久化 | **已有雏形（仅同一轮多结果集）** | **H-02** |
| 结果列拖拽重排 | DBX 列头拖动 / 布局；DBeaver 列顺序 | `ResultGrid` 有列宽、隐藏、冻结、排序，没有列顺序；`TableDataView` 同样没有；G-04 明确写了「第一版不做列顺序」 | **完全缺失** | **H-03** |
| 结果转置 | DBX Transposed View；DBeaver Record 视图 | 只有行详情 / 表单视图（一次一行纵向看），没有矩阵转置；结果网格没有转置入口 | **完全缺失** | **H-03** |
| 连接健康检查 / 断线提示 | Navicat Keepalive / 自动重连 | 连接 chip 只在连接 / 刷新时显示 `idle / connecting / connected / failed`；查询失败只写 `tab.error`；没有周期检查、断线状态或全局提示 | **完全缺失** | **H-04** |
| 自动重连 | Navicat 自动重连；DBX 重连 | 驱动缓存在 `AppState.drivers`；保存 / 编辑连接会丢弃缓存；SQLx 池可能在 acquire 时重建连接，但 SSH 隧道、Redis 客户端和 UI 状态不会自动恢复 | **完全缺失（应用层）** | **H-04** |
| 列剖析（分布 / 统计） | Navicat Data Profiling；DBeaver Calc | G-01 只对**选区**做统计；G-03 图表需要手动选 X / Y；没有「按列」的质量、NULL 比例、distinct、分布、Top 值面板 | **已有雏形（仅选区统计）** | **H-05** |
| 粘贴覆盖已有行 / 区域粘贴 | DBX 只支持粘贴新增；DBeaver 网格可编辑 | F-04 只追加待提交新增；表数据只有行复选框选择，没有单元格 / 矩形选区；覆盖写还涉及行定位、主键、无主键、类型转换与撤销 | **完全缺失** | **不做，见 0.6** |
| 跨驱动数据传输 / 逐列映射 | DBeaver Data migration 列映射 / 变换；DBX 数据传输 | `transfer.rs` 明确拒绝不同 driver；只按同名字段映射；没有目标列映射、类型转换、表达式、dry-run | **已有雏形（同驱动同名字段）** | **不做，见 0.6** |
| 可视化现有表设计器 | Navicat Table Designer | `TableStructureView` 可增删改字段 / 索引 / 外键，`CreateTableDialog` 可建新表；没有把现有表放进一个可视化设计器统一编排字段顺序、触发器、选项、批量 SQL 预览 | **已有雏形** | **不做，见 0.6** |
| 查询结果保存为数据集 / 报表 | Navicat 报表 / 查询结果；DBeaver 结果导出 | 有 CSV / JSON / Markdown / SQL / XLSX 导出、图表 SVG 导出；没有可命名、可重开、可刷新、可分享的数据集或报表 | **完全缺失** | **不做，见 0.6** |
| 对象树 / 标签进一步提效 | DBX 对象树 / 标签；Navicat 对象筛选 | 已有对象搜索、常用置顶、批量操作、标签拖动 / 固定 / 溢出 / 重开、分屏、独立窗口、命令面板；没有明显高频缺口 | **已有更好方案** | **不做，见 0.6** |
| 连接 keepalive 配置 / 后台常驻 | Navicat Keepalive Interval | 连接配置没有 keepalive 字段；应用没有后台常驻；只有连接池 | **完全缺失** | **不做，H-04 只做前台健康检查 / 重连** |
| 全表数据剖析 | Navicat Data Profiling | 当前只能读取表数据分页；没有服务端聚合 / 分布命令 | **完全缺失** | **不做，H-05 只做已加载结果 / 当前页** |

**结论**：mydb 的重能力（同步、备份、导入、文档、服务器活动、SQL 文件、结构编辑）已经比较完整；当前最影响日常使用的是**结果生命周期（固定 / 对比）、对象导航（点开表 / 列）、宽表布局（列顺序 / 转置）、断线恢复，以及按列理解数据**。本批五项都落在现有查询工作区、结果网格、表数据、连接状态与设置上；只有 H-04 新增少量后端命令，其余为纯前端。

## H-01 SQL 中 Cmd/Ctrl+Click 打开表与定位列

- **优先级**：P0
- **状态**：已完成（2026-11-26：SQL 表 / 列导航、Cmd/Ctrl+Click、F12、分屏路由、悬停下划线、缺表提示）
- **范围**：前端（`src/components/SqlEditor.vue`、`src/components/QueryWorkspace.vue`、`src/App.vue`、`src/components/TableStructureView.vue`、新增 `src/lib/sql-navigation.ts`、`src/lib/sql-check.ts` 仅导出可复用的表引用解析、`src/styles.css`）；不涉及后端和数据库。
- **用户问题 / 场景**：写一条包含多张表、多个别名的 SQL 时，想确认 `u.email` 到底是哪张表的列、`orders.status` 现在有哪些值，只能去对象树里搜表、再展开字段，或者打开「全局对象搜索」；SQL 文本本身不能点。DBX 的 `Ctrl/Cmd+Click` 可以直接从 SQL 打开表或定位对象，这是编辑器最基本的导航能力。

### 现状核对（基于 2026-11-26 代码）

- `SqlEditor.vue` 已经接收 `completionTables: ScopeTableColumns[]`，用于 CodeMirror SQL 补全；`completionTables` 由当前连接 / 库 / 模式加载，包含表 / 视图 / 物化视图及字段。
- G-05 `src/lib/sql-check.ts` 已实现带位置的 `tokenizeSql()`，内部有 `readTableRef()`、别名识别、CTE 跳过、表 / 列校验等逻辑；但 `TableRef` 等 helper 未导出，当前只服务于静态检查。
- `App.vue::openTableTabAt(table, mode, focusedIndex, forceNew)` 已支持打开数据 / 结构标签；`TableStructureView.vue` 已有 `focusIndex` 属性用于定位索引，但没有 `focusColumn`。
- 当前没有 SQL 编辑器点击导航；全局对象搜索、命令面板、对象树搜索是三条独立路径。
- **现状标注：完全缺失。**

### 期望行为（可验收细节）

1. **入口与修饰键**
   - macOS 使用 `Cmd+Click`，Windows / Linux 使用 `Ctrl+Click`；实现上接受 `event.metaKey || event.ctrlKey`，不依赖平台判断。
   - 仅在 SQL 编辑器的 CodeMirror 区域内生效；不在结果网格、表数据、输入框或对话框内生效。
   - `F12` 作为键盘等价入口：对光标所在 token 执行同样的导航；不新增全局快捷键，快捷键速查表补充一条「打开光标处对象」。
   - 普通单击、双击选词、拖选、右键菜单、`Cmd/Ctrl+F` 查找保持原行为；`Cmd/Ctrl+Click` 阻止默认的文本选择扩展，避免同时改变选区。

2. **可点击 token 与解析**
   - **表引用**：识别 `FROM`、`JOIN`、`UPDATE`、`INSERT INTO`、`DELETE FROM`、`ALTER TABLE`、`TRUNCATE TABLE` 后的表名；支持 `schema.table` / `database.table`、双引号 / 反引号 / 方括号引用；取最后一段作为当前 scope 的表名，前缀只用于显示与消歧。
   - **列引用**：识别 `table.column`、`alias.column` 与简单单表语句中的裸列名；点击列打开对应表的结构并定位该列。无法唯一确定所属表（JOIN、子查询、CTE、表达式、函数参数、SELECT 别名）时宁可不导航，给出轻提示「无法确定该列所属表」。
   - **别名**：解析 `FROM users u`、`FROM users AS u`、`JOIN orders o ON ...`；点击别名 `u` / `o` 可打开对应表（别名唯一时）；点击 `u.email` 打开 `users` 结构并定位 `email`。别名重复或 CTE 同名时按「不导航」处理。
   - **CTE 与子查询**：CTE 名称（`WITH recent AS ...` 的 `recent`）不导航；CTE 内部的真实表名仍可导航；子查询内的表 / 列按同样规则处理，无法确定时跳过。
   - **字符串 / 注释 / 参数**：tokenizer 已排除字符串与注释；`'users'`、`-- users`、`/* users */`、`:name`、`?`、`$1` 不导航。
   - **大小写**：未加引号的标识符按驱动规则比较（MySQL / SQLite 大小写不敏感；PostgreSQL 未加引号折叠为小写）；加引号的标识符按原样比较；不得把 `"User"` 与 `user` 当作同一个对象。
   - **元数据缺失**：`completionTables` 为空或 token 不在当前 scope 时，显示「未在当前库 / 模式找到表 xxx；可刷新对象树后重试」，不发起数据库请求、不自动刷新、不弹出阻塞对话框。
   - **对象类型**：表 / 视图 / 物化视图可导航；存储过程 / 函数 / 触发器 / 序列 / 索引不在本项范围，点击时提示「该对象暂不支持从此处打开」。

3. **导航目标与标签行为**
   - 表 token：打开该表的「数据」标签；列 token：打开该表的「结构」标签并高亮该列。
   - 目标来源使用**当前查询标签**的 `connectionId / database / schema`，而不是盲目使用当前选中连接；如果该来源尚未成为活动上下文，先复用现有标签切换逻辑切过去。
   - 普通导航复用同来源、同对象的已有表标签（与对象树单击一致），不强制新建；不改变标签顺序、固定状态和当前查询标签内容。
   - 列高亮：`TableStructureView` 新增 `focusColumn` 属性，滚动到字段行并显示 1.5 秒高亮；结构页加载中时排队，加载完成后定位；找不到列时提示并停留在结构页。
   - **分屏查询**：从右侧分屏查询触发时，在右侧分屏打开对应表（只读），左侧查询保持不变；不关闭分屏、不切换左侧标签。
   - **独立查询窗口**：本期不新增跨窗口表标签路由；在独立查询窗口中触发时提示「请在主窗口打开对象」，不静默失败。此限制写入已知限制。
   - 只读连接同样可以导航（只读不阻止查看数据 / 结构）。

4. **视觉与反馈**
   - 按住 `Cmd/Ctrl` 悬停在可导航 token 上时，显示下划线与手型光标；移开修饰键或离开 token 后恢复。普通悬停不显示，避免编辑器里到处是链接样式。
   - 导航成功：表标签出现并激活（或分屏出现），状态栏显示「已打开表 users」；不弹出 toast 打断。
   - 导航失败：使用现有状态栏 / 轻量 toast，不阻塞编辑；不修改 SQL、不写执行历史、不触发查询。
   - 解析耗时超过 50ms 时不显示 hover 装饰，避免大 SQL 卡顿；点击仍然可用。

5. **与现有能力的关系**
   - 不替代 SQL 补全、G-05 静态检查、全局对象搜索、F-03 外键跳转；它是从 SQL 文本到对象的第四条路径。
   - 不检查 SQL 正确性、不执行 SQL、不打开事务；即使 SQL 有语法错误，只要能解析出表 / 列 token 仍可导航。
   - 点击 `SELECT * FROM users` 中的 `users` 打开数据；点击 `*` 不导航；点击 `SELECT`、`FROM` 等关键字不导航。

### 数据与存储

- 不新增 localStorage / 配置文件 / 数据库表；不缓存解析结果到磁盘。
- 解析结果与 hover 状态只在编辑器组件内存中；切换标签、关闭标签即释放。
- 不读取新的元数据：只使用当前 `completionTables`；元数据过期时提示用户刷新对象树，不自动发起请求。

### 失败与边界

- **元数据未加载 / 为空**：不导航，提示刷新对象树；不误报、不弹错误对话框。
- **同名对象**：当前 scope 内表与视图同名时优先表；仍然歧义时给出「找到多个同名对象」提示，不随意打开。
- **别名歧义**：同一别名被多张表使用、CTE 与真实表同名、子查询遮蔽时，按不导航处理。
- **引号 / 大小写**：引号标识符按原样匹配；未加引号按驱动折叠规则；匹配失败时提示未找到，不做模糊猜测。
- **SQL 过大**：超过 G-05 的 100 KB / 5,000 token 上限时，点击提示「SQL 过大，暂不支持导航」，不阻塞编辑器。
- **对象被删除**：导航时对象已不存在，提示「对象已不存在，请刷新对象树」；不自动创建标签。
- **分屏 / 独立窗口**：分屏按上述规则打开右侧表；独立窗口明确提示在主窗口打开。
- **只读 / 无权限**：只读连接可导航；无权限时打开标签后由现有数据 / 结构页显示数据库错误，不在导航层拦截。
- **点击与选区**：`Cmd/Ctrl+Click` 不改变当前选区；如果用户先选中文本再 Cmd+Click，仍按点击位置导航，不清空选区。

### 性能 / 上限

- 点击时按需 tokenize 当前文档，最多 100 KB / 5,000 token；100 KB 文档解析目标 < 50ms。
- hover 检测按 token 位置做，50ms 节流；不注册全局 mousemove，不扫描整个 DOM。
- 不新增数据库请求；表标签打开沿用现有元数据与读取逻辑。
- 不缓存跨文档 token；切换文档版本后重新解析。

### 明确不做

- 不做导航历史 / 前进后退；不做跨连接、跨库、跨 schema 的点击跳转。
- 不做函数、类型、CTE 定义、触发器、索引的跳转；不做「转到定义」的完整语义层。
- 不执行 SQL、不预览数据、不打开事务、不写执行历史。
- 不在结果网格、表数据、ER 图、对象树中增加点击导航；这些已有各自入口。

### 风险 / 限制

- **别名 / CTE / 子查询解析**是最大风险：轻量 tokenizer 不是完整 SQL 解析器，别名遮蔽、`USING`、`NATURAL JOIN`、窗口函数、嵌套子查询都可能无法唯一解析。第一版必须坚持「不确定就不导航」，不能猜。
- **大小写 / 引号规则**按驱动不同；统一大小写不敏感会在 PostgreSQL 引号标识符上误开对象。必须复用 G-05 已有的 token 比较规则，并在验收中覆盖。
- **元数据过期**：`completionTables` 可能落后于 DDL；导航失败时提示刷新，不自动刷新，避免在点击时触发额外请求。
- **点击与编辑器交互**：`Cmd+Click` 在 macOS 也可能用于多光标 / 选择；必须在编辑器层阻止默认行为，同时保留普通点击与拖选。建议只拦截带修饰键的单击，不拦截双击。
- **分屏 / 独立窗口路由**：分屏可直接复用现有表标签能力；独立窗口的表标签能力不明确，第一版明确不支持，避免引入跨窗口事件与权限问题。
- **性能**：100 KB / 5,000 token 上限内同步解析；超过上限提示，不做后台 worker。

## H-02 结果固定（Pin）与多轮运行对比

- **优先级**：P0
- **状态**：已完成（2026-11-26：固定结果 / 命名 / 取消 / 上限、实时与固定隔离、对比对话框、差异复制、固定导出）
- **范围**：前端（`src/components/QueryWorkspace.vue`、`src/components/ResultGrid.vue`、`src/App.vue` 的 `QueryTab` 模型、新增 `src/components/PinnedResultBar.vue`、新增 `src/components/ResultCompareDialog.vue`、新增 `src/lib/result-compare.ts`、`src/styles.css`）；不涉及后端和数据库。
- **用户问题 / 场景**：执行 `SELECT ... WHERE status = 'paid'` 得到 120 行，改完数据或改完 SQL 后再执行，上一次结果被直接替换；无法确认「刚才到底是多少行」「哪些行新增 / 删除 / 金额变了」。多语句的「结果 1 / 结果 2」只是同一轮运行的切换，下一次运行同样会消失。Navicat / DBeaver 都支持固定结果标签，DBX 也支持保留多次运行用于对比。

### 现状核对（基于 2026-11-26 代码）

- `QueryTab` 有 `result: QueryResult | null`、`resultSets: QueryResult[]`、`resultSetIndex`；一次运行开始时会清空 `resultSets`（单语句 `tab.resultSets = []`，多语句同样重置），完成后用新结果替换。
- `QueryWorkspace.vue` 用 `resultSets` 渲染「结果 1 / 结果 2」标签；`ResultGrid` 只有一个实例，`result` 变化时清空筛选、排序、隐藏列、选区、列宽等本地状态。
- 结果只存在于内存；查询标签会持久化 SQL / 来源，但结果、事务、选中文本不持久化。
- 结果导出、F-02 筛选、G-01 选区统计、G-03 图表都已存在，可以复用；没有固定、命名、对比。
- **现状标注：已有雏形（仅同一轮多语句结果集），跨运行固定 / 对比完全缺失。**

### 期望行为（可验收细节）

1. **固定入口**
   - 结果工具栏新增「固定」按钮（`pin` 图标），仅在当前结果 `isQuery === true`、`rows.length > 0`、不在运行中、没有执行失败时可用；非查询结果、空结果、运行中禁用并说明原因。
   - 多语句运行时，固定当前选中的「结果 N」；固定按钮旁或结果集标签右键提供「固定此结果」。
   - 固定后结果工具栏旁出现固定结果条；首次固定给出轻提示「已固定结果 1；重新执行不会覆盖」。
   - 固定数量上限：每个查询标签最多 10 个；达到上限时禁用并提示「每个查询标签最多固定 10 个结果，请先取消一个」。

2. **固定内容**
   - 固定的是**当前结果集的原始查询结果**：`columns`、`rows`、`rowsAffected`、`elapsedMs`、`truncated`、`isQuery`，加上固定时的标签标题、SQL 文本快照、连接 / 库 / 模式、结果集序号、时间戳。
   - **不固定 F-02 本地筛选、结果网格排序、隐藏列、列宽、冻结、选区**。固定条和固定视图明确显示「原始结果 N 行（不含本地筛选 / 排序）」。用户可以在固定视图上重新筛选 / 排序。
   - 固定时对结果做深拷贝（优先 `structuredClone`，失败回退 JSON 序列化）；固定后实时结果的变化、重新执行、切换结果集都不得修改已固定内容。

3. **固定结果条**
   - 位置：结果工具栏下方、「结果 1 / 结果 2」标签上方；横向可滚动；每项显示 pin 图标、名称、行数、固定时间。
   - 默认名称：`结果 N · HH:mm:ss`（N 为固定时的结果集序号；单结果集用 `结果 · HH:mm:ss`）；名称可重命名，1–60 字符，同标签内不允许重名（重名自动追加 ` (2)` 或提示）。
   - 点击固定项：切换到固定视图；当前固定项有选中态；再次点击当前固定项或点击「实时结果」返回实时结果。
   - 右键菜单：重命名…、取消固定、与当前结果对比…、与另一个固定结果对比…、导出固定结果…、复制固定时的 SQL。
   - 固定项右侧提供「取消固定」icon button；取消当前正在查看的固定项后回到实时结果；取消不弹确认（固定是会话内只读快照，取消不丢数据库数据），但保留一次 toast「已取消固定」。

4. **固定视图**
   - 固定视图使用**独立的 ResultGrid 实例**，与实时结果网格同时挂载、用 `v-show` 切换；实时网格的筛选、排序、隐藏列、冻结、选区、滚动位置在切到固定视图后保持不变，切回时恢复。
   - 固定视图是只读快照：支持排序、F-02 筛选、E-01 查找、G-01 选区统计、G-03 图表、导出、复制、值查看器、行详情；不支持编辑（查询结果本来就只读）、不重新查询数据库。
   - 固定视图顶部显示横幅：「固定结果 · 名称 · 固定于 HH:mm:ss · N 行 · 不代表数据库当前状态」；旁边提供「返回实时结果」。
   - 固定视图的筛选 / 排序 / 隐藏 / 列宽只影响该固定视图的临时显示；不写回固定快照，也不影响实时网格；关闭固定视图或切换固定项后可丢弃这些临时状态。
   - 固定视图的导出使用固定快照（加上当前固定视图的可见列 / 排序 / 筛选），文件名默认包含固定名称与时间戳；实时结果后续变化不影响导出。
   - 固定视图切换到图表 / 剖析（H-05 落地后）使用固定快照；切回实时结果时图表 / 筛选状态按现有逻辑恢复。

5. **多结果集与多标签**
   - 多语句运行后，每个「结果 N」都可以单独固定；固定项记录 `resultSetIndex` 与当时的 SQL 快照；固定项名称默认包含「结果 N」。
   - 固定结果按查询标签隔离：切换标签、分屏、独立查询窗口各自维护；关闭标签时释放该标签的固定结果；重新打开 SQL 文件 / 查询标签不会恢复固定结果。
   - 切换连接 / 库 / 模式不会清空已固定结果；固定结果仍可查看 / 导出，但其来源信息只用于展示，不用于重新执行。
   - 不跨标签 / 跨窗口对比；对比对话框只列出当前标签的固定项 + 当前实时结果。

6. **对比入口与对象**
   - 固定项右键「与当前结果对比…」：基准为当前固定项，目标为当前实时结果；实时结果为空 / 运行中 / 失败时禁用并说明。
   - 固定项右键「与另一个固定结果对比…」：打开对比对话框，选择基准与目标；两者都来自当前标签的固定项。
   - 对比对话框也可以从固定结果条的「对比」按钮打开，默认基准为最近固定的结果、目标为当前实时结果。
   - 对比对象必须都是 `isQuery === true`；非查询结果 / 空结果 / 运行中不可选。

7. **对比结构**
   - **列对齐**：按列名比较；列名重复时使用 `名称#序号`（序号按结果列顺序，从 1 开始）作为稳定键。两边列集合不一致时，显示「仅基准有」「仅目标有」的列清单，并默认只比较共同列；没有共同列时只显示结构差异，不做行对比。
   - **行键**：用户选择一个共同列作为键（下拉，默认规则见下）；若键列在任一侧存在 NULL 或重复值，阻止键匹配并提示「该列存在 NULL / 重复值，无法唯一匹配行；请换一列或改用按行号对比」。
   - 默认键选择：优先选择列名严格等于 `id` 且两侧值唯一非 NULL 的列；否则选择第一个两侧值唯一非 NULL 的列；否则使用「按行号对比」。按行号对比时显示警示「结果顺序变化会产生假差异；建议选择唯一键列」。
   - 键比较使用显示值（`formatGridCell`），大小写敏感；NULL 不参与键匹配。列值比较也使用显示值，NULL 与空串视为不同；数字 `1` 与字符串 `"1"` 显示相同则视为相同（在对话框说明「按显示值比较」）。

8. **对比结果**
   - 顶部摘要：基准行数、目标行数、新增（仅目标）、删除（仅基准）、修改（同键但至少一个共同列显示值不同）、未变；共同列数、结构差异数。
   - 主体：左右并排表格，左侧「基准」、右侧「目标」；按状态分组或按键排序；新增行绿色、删除行红色、修改行黄色；修改单元格在两侧同时高亮；提供「只看差异」开关（默认开）。
   - 行数上限：1000 行 / 200 列（与查询结果上限一致）；超过时只比较前 1000 行并提示。对比计算目标 < 200ms（1000 × 100）。
   - 复制：支持「复制摘要」（TSV / Markdown）与「复制差异表」（TSV）；不生成 UPDATE / INSERT 补丁 SQL，不做三路合并，不写数据库。
   - 关闭对话框不改变固定项、实时结果、筛选、排序与导出状态；重新对比使用打开时的快照（若基准 / 目标在对话框打开期间被取消固定，提示并关闭）。

9. **运行、失败与生命周期**
   - 运行中固定按钮禁用；已有固定项保留；查询失败不清空固定项；重新执行成功也不清空固定项。
   - 固定项不持久化到 localStorage / 配置文件；应用重启、窗口关闭、标签关闭后丢失；固定条上可提示「仅本次会话」。
   - 固定快照占用内存上限：单个固定项估算序列化大小 ≤ 10 MB，每标签 ≤ 50 MB，最多 10 个；超过时拒绝固定并提示「固定结果过大，请先导出或缩小结果」；不得只固定一半。
   - 查询结果已被截断（`truncated`）时，固定条与对比对话框显示「结果已截断，只固定已加载的 N 行」。

10. **与现有功能的关系**
   - F-02 筛选：实时 / 固定两个网格各自维护筛选状态；固定快照本身不含筛选；对比使用固定快照的原始行。用户在固定视图上筛选后再对比，仍按原始行对比（对话框说明）。
   - G-01 选区统计 / G-03 图表：作用于当前显示网格（实时或固定）；切换网格时重新计算，不串状态。
   - G-02 表数据导出：不受影响；固定结果导出走结果导出对话框，不是表数据导出。
   - E-02 行详情 / B-16 值查看器：固定视图仍可使用。
   - 多语句「结果 N」：保留现状；固定项与结果集标签是两层，固定项不替代结果集标签。

### 失败与边界

- 当前结果不是查询结果（INSERT / UPDATE / DDL）、空结果、运行中、执行失败：固定按钮禁用并给出原因。
- 固定名称为空 / 超过 60 字符 / 同标签重名：拒绝并提示；重命名失败保留原名。
- 固定数量超限 / 单条或总量超内存：拒绝并提示，不产生半截快照。
- 固定项被取消后仍在对比对话框中被引用：提示「固定结果已取消」并关闭对比。
- 列结构不一致、没有共同列、重复列名、键列 NULL / 重复、按行号对比：按上述规则提示或降级，不静默产生错误差异。
- 结果行数超过 1000（理论上不会，接口上限 1000）：只固定已加载行并显示截断提示。
- 实时结果切换「结果 N」时，固定项保持不变；固定视图切换时不影响实时结果。
- 分屏 / 独立窗口：各自维护固定项；窗口关闭释放；不跨窗口对比。

### 性能 / 上限

- 单个固定项深拷贝 1000 行 × 200 列目标 < 100ms；对比 1000 行 × 100 列目标 < 200ms。
- 固定条最多 10 项，横向滚动；不因固定项增多而重新计算所有快照。
- 固定视图使用与实时网格相同的虚拟滚动 / 筛选 / 排序能力；不复制实现。
- 内存估算用序列化字符长度 × 2（UTF-16 近似）或 `Blob` 大小；超过上限拒绝，不做静默 LRU 淘汰（避免用户以为还在）。

### 明确不做

- 不做固定结果持久化、跨重启恢复、跨标签 / 跨窗口共享。
- 不做三路合并、补丁 SQL、自动同步回数据库、数据修复建议。
- 不做「固定时包含本地筛选 / 排序」的快照模式；固定的是原始结果。
- 不做对比结果的 CSV / JSON 文件导出（第一版只复制到剪贴板；如后续需要可复用结果导出）。
- 不做跨结果列类型转换、忽略大小写 / 数值容差配置；第一版按显示值严格比较。
- 不改变多语句结果集标签、查询执行、取消、超时与历史语义。

### 风险 / 限制

- **内存**：固定是完整行数据副本；1000 行 × 200 列的宽结果可能接近 10 MB。必须有单条 / 总量上限与明确提示，不能静默淘汰。
- **「固定的是原始结果」可能与用户预期不一致**：用户在筛选后固定，会看到全部行。必须用固定条文案、固定横幅和提示反复说明，并在验收中确认。
- **差异语义**：按显示值比较会把 `1` 与 `"1"`、日期字符串与时区差异视为相同 / 不同；必须写明规则，不能宣称「数据库级精确对比」。键列选择、NULL、重复值、列顺序变化都会影响差异结果。
- **重复列名**：`SELECT a.id, b.id` 会产生重复列名；必须用 `名称#序号` 稳定键，并禁止用重复列名做键。
- **双网格状态**：实时 / 固定两个 ResultGrid 同时挂载，筛选、查找、图表、导出工具栏必须明确作用于「当前显示网格」；切换时容易串状态，需逐项验收。
- **固定视图与 H-03 / H-05**：列顺序、转置、剖析都作用在当前网格；实现时要确保固定视图与实时视图各自独立，不共享列顺序 / 筛选 / 剖析缓存。
- **会话内丢失**：固定结果不持久化，关闭标签就没了；这是有意取舍，但用户可能误以为会保存，需要在 UI 中明确「仅本次会话」。

- **优先级**：P1
- **状态**：已完成（2026-11-26：结果列拖拽与冻结块规则、表数据列顺序持久化、视图 `order`、只读转置与复制）

### 数据与存储

- `mydb.tableColumnOrder.v1` 只存列键数组与时间戳，不存行数据、不存 SQL、不存密码。
- `mydb.tableViews.v1` 的 profile 新增可选 `order` 字段；保持 `version: 1`；旧 profile 读取时 `order` 缺失按空处理。
- 结果网格列顺序、转置状态只在内存；不写 localStorage。
- 不写数据库、不写执行历史；拖拽 / 转置不触发任何 `invoke` 数据库命令。

### 失败与边界

- 列拖拽到自身位置、拖出表头、Esc 取消：不改变顺序，不触发排序。
- 拖动过程中结果刷新 / 执行新查询 / 切换标签：终止拖动并丢弃临时顺序；新结果按新列集合恢复或重置。
- 隐藏列全部 / 至少一列：隐藏最后一列时禁用；重排不改变隐藏状态。
- 冻结边界：跨块拖动被拒绝并提示；冻结列被隐藏后，冻结块可能为空，取消冻结状态需保持一致。
- 表视图应用失败：沿用 G-04 的回退逻辑；`order` 引用的列不存在时剪枝，不阻塞筛选 / 排序。
- localStorage 损坏 / 超限：回退 / 提示，不阻塞表打开。
- 转置超过上限：只显示前 500 行 / 100 列并明确提示，不静默丢弃；复制也受同一上限限制。
- 转置中的 NULL / 对象 / 二进制 / 超长文本：沿用结果网格格式化；不尝试编辑。
- 待提交编辑：重排是显示操作，不改变 `updates` / `pendingInserts` / `pendingDeletes`；正在编辑单元格时开始拖动，先提交当前编辑（与现有单元格失焦提交一致），避免输入丢失。
- 视图保存 / 应用与待提交：沿用 G-04 的 `ensureClean` 守卫；列顺序本身不触发守卫。

### 性能 / 上限

- 结果网格最多 1000 行；列重排只调整显示索引数组，不复制行数据，目标 < 16ms。
- 表数据每页最多 500 行；列顺序持久化只写元数据，debounce 300ms。
- 转置最多 500 行 × 100 列 = 50,000 个单元格；第一版使用普通表格 + 横向滚动，不做单元格虚拟化；超过上限直接截断并提示，避免卡顿。
- 列顺序存储每表 500 列、全局 200 张表；单条记录很小，但必须处理配额错误。

### 明确不做

- 不做数据库列顺序修改（`ALTER TABLE ... FIRST/AFTER` / 重建表）；只改客户端显示。
- 不做结果网格列顺序的跨重启持久化；结果本身不持久化。
- 不做表数据转置；不做转置视图内的编辑 / 筛选 / 排序 / 图表 / 剖析。
- 不做跨冻结块的拖拽自动冻结 / 解冻；只提示用户先操作冻结。
- 不做列分组、列折叠、多级表头、列搜索（这些是另一类宽表能力）。
- 不改变列宽 / 隐藏 / 冻结 / 排序 / 导出范围的既有语义；只增加顺序。

## H-04 连接健康检查与断线重连（不自动重放 SQL）

- **优先级**：P1
- **状态**：已完成（2026-11-26：60 秒前台健康检查、断线横幅、单次自动重连、设置开关、事务 / 运行 / 独立窗口保护、后端命令；真实库断网回归待补）
- **范围**：前端（`src/App.vue`、`src/lib/api.ts`、`src/lib/types.ts`、`src/components/SettingsDialog.vue`、新增 `src/lib/connection-health.ts`、`src/styles.css`）；后端（`src-tauri/src/commands/connections.rs`、`src-tauri/src/commands/redis.rs`、`src-tauri/src/commands/context.rs`、`src-tauri/src/lib.rs`）；不新增驱动。
- **用户问题 / 场景**：MySQL 的 `wait_timeout`、云数据库空闲断开、SSH 隧道/NAT 超时、VPN 掉线后，下一次查询报「MySQL server has gone away」「Connection reset by peer」「Broken pipe」；界面仍显示「已连接」，用户不知道是 SQL 错还是连接断了，只能编辑连接、切换数据库或重启应用。Navicat 提供 keepalive 与断线自动重连；mydb 目前没有健康检查、没有断线提示、没有重连命令。

### 现状核对（基于 2026-11-26 代码）

- `App.vue` 的 `ConnectionStatus` 只有 `idle / connecting / connected / failed`；`connectionStatusLabel` 只在连接 / 刷新对象时更新；查询失败只写 `tab.error`，不改变连接状态。
- `AppState.drivers` 缓存 `Arc<dyn DatabaseDriver>`；MySQL / PostgreSQL 驱动各自持有 SQLx Pool 与可选 `SshTunnel`；Redis 客户端缓存在 `redis_clients`，隧道在 `redis_tunnels`，选库在 `redis_databases`。
- `connections.rs::driver_for` 首次创建并缓存驱动；保存 / 编辑 / 删除连接会移除缓存，下一次请求重连；`switch_database` / `switch_schema` 会重建或切换上下文。
- SQLx Pool 在 acquire 时可能自动建立新连接，因此「服务端重启」后部分查询可能自动恢复；但 SSH 隧道任务死亡、Redis 客户端断开、UI 状态与事务上下文不会自动恢复。当前没有 `check_connection_health` / `reconnect_connection` 命令。
- 连接配置没有 keepalive 字段；没有周期健康检查；没有断线横幅；没有自动重连设置。
- **现状标注：连接健康检查 / 断线提示完全缺失；自动重连在应用层完全缺失（SQLx 池有隐式重连，但不足以覆盖 SSH / Redis / UI）。**

### 期望行为（可验收细节）

1. **健康检查**
   - 新增只读后端命令 `check_connection_health(connection_id)`：SQLite / MySQL / PostgreSQL 调用 `driver.test_connection()`（`SELECT 1`）；Redis 调用 `redis_ping`；外层 5 秒超时；不写执行历史、不写业务数据。
   - 前端只对**当前活动连接**做检查：每 60 秒一次；条件为 `connectionStatus === "connected"`、窗口可见（`document.visibilityState === "visible"`）、没有运行中的查询、没有未提交事务；同一连接最多一个在途检查。
   - 窗口从隐藏恢复可见时，如果距离上次检查超过 60 秒，立即检查一次；切换连接时重置计时器。
   - 健康检查成功：不弹 toast、不改变状态、不刷新对象树；仅更新内部 `lastHealthyAt`。
   - 健康检查失败：标记连接为「断开」，停止该连接的定时检查，显示断线横幅；不要直接把对象树清空。

2. **断线检测（错误分类）**
   - 新增 `src/lib/connection-health.ts`：`isConnectionLostError(message: string): boolean`，基于保守模式匹配，例如 `MySQL server has gone away`、`Lost connection to MySQL server`、`server closed the connection unexpectedly`、`Connection reset by peer`、`Broken pipe`、`unexpected EOF`、`SSL connection has been closed`、`terminating connection due to administrator command`、`connection is closed`、`connection timed out`（仅连接阶段，不匹配应用层「查询超时」）。
   - 明确排除：应用层 `查询超时`、`已取消`、语法错误、权限错误、约束冲突、只读拦截、表不存在；这些只显示原有错误，不标记断线。
   - 应用位置：查询执行失败、对象树刷新失败、表数据读取失败、执行计划失败、结构 / 同步等读取失败。第一版至少覆盖查询执行 + 对象树刷新 + 表数据读取；通过统一的 API 错误回调或显式 emit 把错误交给 App 判断，避免每个组件各写一套。
   - 只有**当前活动连接**的错误触发全局断线状态；后台标签的错误仍写入各自 `tab.error`，但可在标签上显示断线标记（可选）。

3. **断线状态与横幅**
   - `ConnectionStatus` 新增 `"lost"`（或 `failed` + `disconnected: true`）；状态标签「连接已断开」；连接 chip 的状态点使用危险色。
   - 在工作区上方显示持久横幅：`role="alert"`；文案「连接可能已断开：<原始错误摘要>」；按钮「重新连接」「忽略」；如果自动重连开启，显示「正在尝试重新连接…」。
   - 横幅不遮挡 SQL 编辑器，不关闭标签、不清空 SQL、不清空结果、不清空固定结果、不自动回滚事务；用户仍可阅读 / 复制现有结果。
   - 「忽略」只隐藏横幅，状态保持「断开」；下一次失败 / 手动检查可再次显示。
   - 重连成功后横幅变为轻提示「已重新连接；请重新执行刚才的语句」，3 秒后消失；不自动重跑 SQL。
   - 重连失败：横幅保留，显示原始错误；按钮变为「重试」；不要循环弹窗。

4. **重连命令与安全边界**
   - 新增后端命令 `reconnect_connection(connection_id)`：
     - 拒绝条件：该连接存在未提交事务（`state.transactions` 中有对应 connection_id）、存在运行中的查询（`state.running_queries`）、存在独立查询窗口使用该连接（`state.query_windows`）、连接正在关闭 / 删除。返回明确中文错误，不静默回滚。
     - 捕获旧上下文：`driver.context()` 得到当前 database / schema；Redis 读取 `redis_databases` 当前库。
     - 移除 `state.drivers` 缓存（触发旧 Pool / SshTunnel Drop）；SQLite / MySQL / PostgreSQL 优先按旧 database / schema 调用 `isolated_driver_for` 重建，再 `test_connection()`，成功后写回 `state.drivers`；旧上下文为空时用 `driver_for`。
     - PostgreSQL 旧 database 不存在 / 无权限：返回明确错误，不自动切到默认库；MySQL 旧 database 不存在：返回明确错误；SQLite 文件不存在 / 被移动：返回文件错误。
     - Redis：移除 `redis_clients` / `redis_tunnels`，重新 `redis_connection`（复用 `redis_databases` 选库），`PING` 成功后写回；Cluster 仍按现有规则只允许 db0。
     - 清除 / 重置该连接的 `server_samples`（QPS 采样）可选；不影响其他连接。
     - 不执行任何用户 SQL；不写执行历史；不修改连接配置、密码、钥匙串。
   - 重连成功后返回新的 `ConnectionContext`；前端更新状态、库 / 模式标签，并调用现有 `refreshTables()` 恢复对象树；保留查询标签、SQL、结果、固定结果与表标签；表标签如果因对象不存在而读取失败，显示原有错误，不自动关闭。
   - 重连失败返回原始错误；前端保持「断开」状态与横幅；不重试用户 SQL。

5. **自动重连**
   - 设置中心新增「连接」分区：开关「断线后自动重连（不会重新执行 SQL）」，默认**开启**；存储在 `mydb.autoReconnect.v1`（`"1"` / `"0"`，缺省按开启）；重启保持。
   - 触发条件：检测到连接级错误 / 健康检查失败，且当前连接满足安全边界（无事务、无运行查询、无独立窗口）；每个「断线事件」最多自动尝试 1 次；成功后显示提示；失败后不再自动循环，等待用户点「重试」。
   - 自动重连期间不阻塞编辑器 / 结果 / 标签；按钮显示旋转 / 禁用；用户可继续阅读现有内容。
   - 自动重连成功后**不自动重新执行**失败语句，也不自动重试表数据读取；由用户手动重跑。这是硬约束，避免写语句重复执行。
   - 自动重连关闭时：只显示横幅与手动按钮；健康检查仍运行（只检测，不重连）。

6. **事务 / 运行中 / 多窗口边界**
   - 有未提交事务：不自动重连；手动重连也拒绝，提示「该连接有未提交事务，请先提交或回滚」；不得自动回滚（事务可能包含用户未保存的工作）。
   - 查询运行中：不自动重连；手动按钮禁用并提示「查询执行中，请先停止或等待完成」；查询结束后可重试。
   - 独立查询窗口使用该连接：拒绝重连，提示「独立查询窗口正在使用该连接，请先关闭」；避免窗口上下文被换掉。
   - 分屏查询与主窗口共享连接：分屏本身不阻止重连，但重连会重建驱动；如果有分屏正在运行查询，按「查询运行中」拒绝；如果只是打开，重连后分屏仍可用（同一 connectionId）。
   - 只读连接：健康检查 / 重连照常；不改变只读标记。
   - 连接被删除 / 编辑：取消计时器、关闭横幅、不重连；下一次选择连接重新开始。

7. **Redis 适用范围**
   - Redis 健康检查使用 `redis_ping`；断线检测同样适用；重连复用 `redis_connection`，保持当前逻辑库（`redis_databases`）与 Cluster 规则。
   - Redis 控制台打开时显示同样的断线横幅；重连成功后不自动重跑上一条命令。
   - Redis 的「重新打开控制台」现有路径保持不变；不新增 Redis 专用设置。

8. **不改变的行为**
   - 不改变查询执行、取消、超时、事务、历史、结果、标签、对象树语义；断线只影响状态提示与连接重建。
   - 不改变连接配置表单的字段（本期不做 keepalive interval 配置）；不要求用户重新输入密码；如果密码已失效，重连返回认证错误，用户可编辑连接。
   - 不新增后台进程 / 系统服务；应用关闭即停止健康检查。

### 数据与存储

- 前端设置：`mydb.autoReconnect.v1`，只存开关；不存密码、不存连接配置。
- 断线状态、`lastHealthyAt`、定时器只在 `App.vue` 内存；不持久化；应用重启后重新连接 / 检查。
- 后端不新增持久化状态；`AppState` 可新增 `last_health` 之类的内存字段（可选），不写磁盘。
- 不写数据库、不写执行历史、不修改 `connections.json` / 钥匙串。

### 失败与边界

- 健康检查本身失败可能只是瞬时网络抖动：标记「断开」但保留手动重试；自动重连最多一次，避免风暴。
- 连接级错误分类误判：宁可漏判（只显示普通错误）也不要误判（把 SQL 错误当断线、自动重建连接）；模式列表保守，遇到未知错误不自动重连。
- 重连与正在结束的查询竞态：先检查运行中查询；若查询在检查后开始，后端重连前再次检查；重连成功后旧查询的取消 / 结果可能失效，前端应丢弃旧 operation 的迟到结果（复用现有标签存在性检查）。
- 旧事务 / 会话临时表 / `SET` 会话变量在重连后丢失；这是重连的固有限制，提示「会话状态已重置」。
- SSH 主机密钥变化 / 私钥口令错误：返回原有安全错误，不自动绕过。
- SQLite 文件被删除 / 移动 / 只读：返回明确错误；不创建空数据库。
- 连接被删除 / 编辑：取消定时器与横幅；避免对已删除连接重连。
- 多连接：只检查当前活动连接；切换连接时清理上一个连接的计时器与横幅；后台连接不轮询。
- 自动重连关闭 / 打开切换：立即生效；关闭时如有进行中的自动重连，让它完成并只更新状态，不再发起新的。
- 应用隐藏 / 睡眠唤醒：隐藏期间不检查；唤醒后如果超过 60 秒，检查一次；避免大量补跑。

### 性能 / 上限

- 健康检查每 60 秒一次、每个活动连接最多 1 个在途、5 秒超时；不并发扫描所有连接。
- 重连目标 < 10 秒（受网络 / SSH 握手影响）；期间 UI 不冻结，按钮显示进度。
- 自动重连每个断线事件最多 1 次，无指数退避循环；用户手动重试不受次数限制（但需点击）。
- 断线检测是同步字符串匹配，< 1ms；不阻塞查询错误展示。

### 明确不做

- 不自动重放 SQL、不自动提交 / 回滚事务、不恢复会话临时表 / 变量。
- 不做可配置 keepalive interval、不做后台常驻、不做系统服务 / 守护进程。
- 不做连接池预热、不做多连接批量健康检查、不做自动切换主从 / 集群节点。
- 不修改连接配置与凭据，不弹出密码输入框（认证失败走现有编辑连接）。
- 不做跨窗口事务恢复、不做查询断点续传。

### 验收标准（可直接在现有 UI / 临时数据库验证）

- [ ] MySQL：连接后执行 `SELECT CONNECTION_ID()` 得到会话 id；在另一条连接执行 `KILL <id>`；原连接下一次查询失败，界面出现「连接可能已断开」横幅，状态 chip 变为「连接已断开」；点击「重新连接」成功，状态恢复「已连接」，对象树刷新，查询标签 / SQL / 结果保留；不自动重跑 SQL。

### 风险 / 限制

- **断线误判**：错误字符串跨驱动 / 版本差异大；模式过宽会把普通错误当断线并自动重建连接。必须保守、可关闭自动重连，并提供「忽略」。
- **事务安全**：重连会丢失事务；必须在任何自动 / 手动重连前检查 `state.transactions`，并明确拒绝，不得自动回滚。
- **运行中查询 / 多窗口竞态**：重连与查询、取消、独立窗口、表数据读取可能并发；后端守卫 + 前端状态双重检查；旧 operation 的迟到结果必须丢弃。
- **会话状态丢失**：临时表、`SET` 变量、锁、`LAST_INSERT_ID` 等在重连后消失；这是固有限制，界面要提示「会话状态已重置」，不能假装恢复。
- **健康检查本身造成负载 / 保活副作用**：每 60 秒 `SELECT 1` 会复用连接，可能改变空闲超时行为；只对活动连接执行，不做全连接轮询。
- **自动重连的用户预期**：用户可能以为会自动重跑 SQL；必须用文案与提示明确「只恢复连接，不重放语句」。
- **Redis 与 SQL 连接生命周期不同**：Redis 重连要保留选库 / Cluster 规则；不要把 SQL 的 database / schema 逻辑套到 Redis。
- **SSH 隧道**：隧道重建依赖私钥 / 密码缓存；如果凭据已清除，需要用户重新编辑连接；不要静默回退明文。

### 验收标准（可直接在 `examples/demo.db` 执行）

- [ ] 执行 `SELECT * FROM orders ORDER BY id`，打开「剖析」：4 行 × 5 列；`id` 为 numeric（min 1 / max 4 / avg 2.5）；`amount` 为 numeric（min 45 / max 1299 / avg 433.125）；`status` 为 text（distinct 3，`paid` 出现 2 次，占 50%）；`created_at` 标记为 date-like；NULL 计数为 0。
- [ ] 执行 `SELECT NULL AS n, '' AS blank, 'x' AS text, 1 AS num, '2' AS num_text, '2026-01-02' AS day`：`n` 全 NULL；`blank` 空白串 1；`num` / `num_text` 数值统计正确并标记「文本数字」；`day` 日期范围正确。
- [ ] 执行混合类型查询（如 `SELECT CASE WHEN id = 1 THEN 1 ELSE 'x' END AS mixed FROM orders`）：`mixed` 标记「混合类型」，数值统计只计算数值项，并显示说明。
- [ ] 开启 F-02 筛选 `status = 'paid'`：剖析只包含 2 行，顶部显示「筛选 1 个条件」；修改筛选后自动重新计算。
- [ ] 隐藏 `email` 列：剖析不再显示 `email`；H-03 列顺序调整后剖析按显示顺序列出；重复列名（`SELECT a.id, b.id ...`）使用 `id#1` / `id#2` 键。
- [ ] 表数据 `orders` 当前页打开「剖析当前页」：显示「当前页 4 行（非全表）」；待提交修改一个单元格后显示「不含待提交修改」，统计仍按数据库值；翻页后重新计算。
- [ ] 点击 `status` 列展开：Top 值显示 `paid` / `pending` / `cancelled` 的次数与百分比；点击 `amount` 展开：10 个数值区间、最小 / 最大标注；NULL / 空白串单独显示。
- [ ] 复制列统计 / 全部统计到剪贴板，内容与屏幕一致；概览 / 详情可用键盘展开，分布条有文字计数与 aria 标签。
- [ ] 1000 行 × 100 列结果剖析 < 200ms；200 列以上只显示前 200 列并提示；行数 / 列数上限不导致 UI 冻结。
- [ ] 剖析不发起数据库请求、不写执行历史、不修改筛选 / 排序 / 隐藏 / 列顺序 / 导出范围；切换结果集、固定 / 实时、表数据翻页后正确重置或重算。
- [ ] 空结果 / 筛选后 0 行显示空状态；全 NULL / 常量 / 对象 / 超长文本不报错。

### 风险 / 限制

- **口径误导**：表数据只剖析当前页，用户可能误以为是全表统计；必须在标题、横幅、复制文本中反复标注「当前页 / 已加载行」，并提供后续全表剖析的明确入口（不在本批）。
- **类型推断不是数据库类型**：没有列元数据，只能根据已加载值推断；数字字符串、日期字符串、混合类型可能判断不完美，必须标记「推断」并提供原始值示例。
- **统计一致性**：distinct / Top 值按显示值还是原始值、NULL 是否计入、空串是否算空值，必须写清楚；建议与 G-01 一致按显示值、NULL 单独、空串单独。
- **性能**：1000 × 200 的概览计算可能超过 200ms；使用单遍扫描、按列懒加载、分片渲染；不要为每列单独排序全部值。
- **重复列名 / 隐藏列 / 列顺序**：列键与显示映射容易错位；统一使用 `名称#序号` 与显示顺序，验收覆盖。
- **与 G-01 / G-03 的重叠**：用户可能问「为什么不直接用选区统计 / 图表」；UI 要说明「剖析是整列体检，G-01 是选中单元格，G-03 是可视化」。剖析不替代两者。
- **可访问性**：分布条如果只用颜色 / 长度，色盲用户无法读取；必须同时显示数字、百分比、文字标签。

## 附录 H-A：测试数据与验证建议

- **SQLite 示例库**：`sqlite3 examples/demo.db < examples/seed.sql`；`users` 4 行 5 列、`orders` 4 行 5 列、`order_items` 4 行 5 列、`active_users` 视图。H-01 / H-02 / H-03 / H-05 都可在该库验证。
- **空值 / 混合类型**：
  ```sql
  SELECT
    NULL AS n,
    '' AS blank,
    '   ' AS spaces,
    'x' AS text,
    1 AS num,
    '2' AS num_text,
    '2026-01-02' AS day,
    '{"a":1}' AS json_text;
  ```
- **宽结果 / 10,000 行（H-03 / H-05 性能）**：
  ```sql
  WITH RECURSIVE cnt(x) AS (
    SELECT 1
    UNION ALL
    SELECT x + 1 FROM cnt WHERE x < 10000
  )
  SELECT x, x * 2 AS double, 'row-' || x AS label, x % 7 AS bucket
  FROM cnt;
  ```
  查询接口默认最多返回 1000 行；验证剖析 / 转置时以 1000 行为上限，另用表数据分页验证当前页。
- **H-01 导航**：
  ```sql
  SELECT u.email, o.amount
  FROM users u
  JOIN orders o ON o.user_id = u.id
  WHERE u.city = '上海'
  ORDER BY o.id;

  WITH recent AS (SELECT * FROM orders) SELECT * FROM recent;
  SELECT 'users', "email" FROM "users";
  ```
- **H-02 固定 / 对比（不写数据库）**：
  ```sql
  SELECT id, status, amount FROM orders ORDER BY id;
  SELECT id, status, amount + 10 AS amount FROM orders ORDER BY id;
  SELECT id, status FROM orders WHERE status = 'paid';
  SELECT id, status FROM orders;
  ```
  第一条固定，第二条对比得到 4 个 amount 修改；第三条固定，第四条对比得到 2 个新增行（`pending` / `cancelled`）。
- **H-03 列顺序 / 转置**：
  ```sql
  SELECT id, name, email, city, created_at FROM users ORDER BY id;
  SELECT * FROM orders WHERE id = 1;
  ```
- **H-04 断线（临时库 / 测试会话）**：
  - MySQL：`SELECT CONNECTION_ID();` 在另一条连接执行 `KILL <id>;`（或 `KILL CONNECTION <id>;`），再在原连接执行查询。
  - PostgreSQL：`SELECT pg_terminate_backend(pg_backend_pid());`，再执行查询。
  - SQLite：把 `examples/demo.db` 临时改名后查询，恢复后重连；不要在真实用户库上做删除。
  - SSH / VPN：断开隧道或网络，等待健康检查 / 执行查询；恢复后手动重连。
  - 事务边界：`BEGIN; UPDATE ...;` 后触发断线，确认自动重连被拒绝、事务未被自动回滚；测试结束手动回滚。
- **H-05 剖析**：`SELECT * FROM orders ORDER BY id`；`SELECT * FROM users ORDER BY id`；配合 F-02 筛选与隐藏列；表数据 `orders` 当前页 4 行。
- **真实 MySQL / PostgreSQL**：按 README 设置 `MYDB_TEST_MYSQL_*` / `MYDB_TEST_PG_*`；H-04 的重连 / 健康检查用临时会话，测试后恢复；H-03 的列顺序只写本机 localStorage，清理测试配置即可。
