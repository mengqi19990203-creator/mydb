- **用户问题 / 场景**：执行完一条查询后，结果只能右键复制全部；想把结果发给同事、贴进文档、留档或再导入，需要手动复制到 Excel/文本再整理，容易丢列、丢格式、丢 NULL 语义。
- **现状核对（2026-11-23，基于当前代码）**：
  - `ResultGrid.vue` 内部持有 `visibleColumns`、`sortedRows`、`sortIndex` / `sortDirection`、`hiddenColumns`；`defineExpose` 目前只暴露 `showAllColumns()`。`QueryWorkspace.vue` 只能拿到 `result` 与 `hiddenColumns` 计数，无法直接得到「当前可见列 + 当前排序」的导出快照。

- **四种格式的精确规则**：
  - **CSV**：
    - UTF-8、无 BOM、`\n` 换行（与表数据页当前页导出保持一致）；文件扩展名 `.csv`。
    - 表头默认包含，可关闭；表头同样按字段规则转义。
    - 值转换：`null` / `undefined` → 空字段；字符串 → 原样；数字/布尔 → `String(value)`；对象/数组 → 紧凑 `JSON.stringify`（不换行、不缩进）。
    - 仅当字段包含 `,`、`"`、`\r`、`\n`，或首尾有空格时加双引号；字段内 `"` 双写为 `""`。
    - 重复列名允许导出（表头重复）；空列名允许，表头为空。
  - **JSON**：
    - 输出对象数组（不是 `{table, columns, rows}` 信封），2 空格缩进，文件末尾保留一个 `\n`；扩展名 `.json`。
    - 每个对象按可见列顺序写入列名键；值保持原始类型：`null` 保持 `null`，数字/布尔不转字符串，JSON/JSONB 对象/数组保持嵌套结构；`undefined` 视为 `null`。
    - 存在重复列名或空列名时禁用 JSON 格式，提示「查询列名重复或为空，请为表达式列设置别名后重新执行」；不得静默覆盖键。
    - 与表数据页 JSON 导出结构不同，对话框用一行说明「本导出为对象数组，表数据页导出为 {table, columns, rows}」。
  - **Markdown**：
    - 标准表格：表头行、`| --- |` 分隔行、数据行；`\n` 换行；扩展名 `.md`。
    - 单元格转义：先 `\` → `\\`，再 `|` → `\|`，CR/LF 统一替换为 `<br>`；`null` → `NULL`，空字符串 → 空单元格；对象/数组 → 紧凑 JSON 后再转义。
    - 重复列名允许；空列名表头留空。
  - **SQL INSERT**：
    - 目标表名为必填输入，支持 `table` 或 `schema.table`（按 `.` 拆分，最多两段）；分段后逐段按驱动加引号：MySQL 反引号（内部反引号双写），PostgreSQL/SQLite 双引号（内部双引号双写）。空段、超过两段、全空白时报错并禁用导出。
    - 每行一条 `INSERT INTO <表> (<可见列>) VALUES (<值>);`，不包 `BEGIN/COMMIT`，不加注释；扩展名 `.sql`。导出列严格等于当前可见列；如需跳过自增主键或某字段，先在网格中隐藏该列。
    - 列名使用结果列名并按单段标识符加引号；表达式列/别名不是真实字段时数据库可能拒绝，对话框提示「SQL INSERT 使用结果列名作为字段名，表达式列请先设置别名」。
    - 值转换：`null`/`undefined` → `NULL`；布尔 → `TRUE` / `FALSE`；数字 → `String(value)`；字符串 → 单引号字符串；对象/数组 → 紧凑 JSON 字符串。
    - 字符串转义：MySQL 先将 `\` → `\\`、NUL → `\0`，再将 `'` → `''`；PostgreSQL/SQLite 先移除 NUL，再将 `'` → `''`。换行/回车保留在字符串字面量内，不额外转义。
    - 存在重复列名或空列名时禁用 SQL INSERT；驱动为 `redis` 时禁用（当前查询工作区不会出现）。
    - DECIMAL/NUMERIC 等以字符串返回的值会按字符串加引号，依赖数据库隐式转换；PostgreSQL 数组/BYTEA、MySQL/SQLite BLOB 仍按文本占位导出，不还原二进制。

  - Markdown 只转义反斜杠、竖线与换行，不转义 HTML 标签；在会渲染原始 HTML 的查看器中打开时需自行注意数据来源。
  - 目标表名按 `.` 拆分为最多两段；若表名本身包含 `.`（需要作为单个标识符引用），本规则会误拆，应在导出后手工修改 SQL，或在数据库中为表使用不含点的名称。
  - 本项不做流式导出、不做「导出选中行」（当前没有行选择模型），也不改变对象右键的全表流式导出。

### B-03 行级快捷复制为 INSERT / UPDATE / JSON

- **优先级**：P1
- **状态**：进行中（代码已完成：TableDataView 复制为子菜单、ResultGrid JSON、共享 row-copy/sql-literal；待真实表与三种驱动验收）

- **现状核对（2026-11-23，基于当前代码）**：
  - `TableDataView.vue` 的 `columns` 是完整 `ColumnInfo[]`（含 `primaryKey`、`autoIncrement`、`nullable`、`dataType`），`rows` 与 `columns` 按索引对齐；当前没有列隐藏功能，所有列都显示；排序/筛选在后端完成，`rows` 顺序就是屏幕顺序。
  - `TableDataView.vue` 目前自带一份 `quoteIdentifier()`，`conditionFor()` 只用 `'` 双写；这与 `sql-literal.ts` 重复，且 MySQL 反斜杠/布尔字面量规则不一致，需要删除并复用。
  - `TableDataView.vue` 只有 `databaseLabel`（展示用，PostgreSQL 可能是 `app · public`），不能可靠解析库/模式；生成限定名需要 App 额外传入 `tab.database` / `tab.schema`。
  - `ResultGrid.vue` 有 `visibleColumns`、`sortedRows`、`hiddenColumns`，但没有表名和主键元数据；B-02 已有 `columnNameIssue()` 和 `ResultExportSnapshot` 可复用。
  - B-02 已有 `sqlLiteral()` / `quoteIdentifier()` / `qualifiedIdentifier()`；B-03 不得再写一套转义。
- **决策摘要（对应六个问题）**：
  1. **表数据页用「复制为」子菜单**，不拆成三个并列项：子菜单放 `INSERT`、`UPDATE`、`JSON`，避免右键菜单过长。复制列 = **全部列**（当前没有列隐藏；不是视口内可见列）。
  2. **查询结果网格只提供「复制为 JSON」，不做 INSERT、不做 UPDATE**：结果没有表名和主键元数据，列可能是表达式/聚合/重复别名，生成的 INSERT 往往不可执行；B-02 已提供带「目标表名」输入的整结果 SQL INSERT，行级 INSERT 属于重复能力。JSON 是结果网格唯一缺失的行级出口。
  3. **JSON 单对象、2 空格缩进、无尾随换行**；嵌套对象/数组保持结构；`null` 保持 `null`，`undefined` 视为 `null`；数字/布尔不转字符串。
  4. **重复/空列名**：表数据页列名来自数据库，正常唯一非空；结果网格用 `columnNameIssue()` 检测，命中时禁用 JSON 项并显示原因。**无主键**：`TableDataView` 的 UPDATE 禁用，INSERT / JSON 仍可用。**只读连接**：复制动作全部允许（复制不是写库）；生成的写 SQL 执行时仍由后端只读守卫拦截。**已排序/隐藏列**：结果网格使用当前 `sortedRows` 中该行的可见列，隐藏列不写入 JSON，成功提示中说明隐藏数量。
  5. **菜单与提示**：点击复制项立即关闭菜单；成功用各组件现有的成功提示（`TableDataView` 的绿色 message bar，`ResultGrid` 的 toast），失败显示「复制失败: 原因」；剪贴板写入不成功时不显示成功。
  6. **验收与复用**：见下方验收标准；`row-copy.ts` 只依赖 `sql-literal.ts` / `generate-sql.ts`，`TableDataView` 删除本地转义实现，所有 SQL 值都走 `sqlLiteral()`。
- **表数据页（TableDataView）实现细节**：
  - **入口**：单元格右键菜单在「复制整行」之后增加「复制为」子菜单；沿用 `ObjectCategoryGroups.vue` 的 `context-submenu-host` / `@mouseenter` / `@mouseleave` 模式。子菜单靠近窗口右边缘时向左展开，底部空间不足时向上偏移；按 Esc 或点击空白关闭。
  - **INSERT**：
    - 目标表：`qualifiedSqlName(driver, table, database, schema)`（MySQL `库.表`，PostgreSQL `模式.表`，SQLite 仅 `"表"`），与对象右键「生成 SQL」保持一致。为此 `TableDataView` 新增 `database?: string | null` / `schema?: string | null` props，App 传入 `tab.database` / `tab.schema`；`databaseLabel` 继续只用于展示。
    - 列：全部 `!autoIncrement` 的列；自增列不写入，允许复制出新行。若没有可写列：MySQL 生成 `INSERT INTO <表> () VALUES ();`，PostgreSQL/SQLite 生成 `INSERT INTO <表> DEFAULT VALUES;`。
    - 值：`sqlLiteral(row[columnIndex], driver)`；NULL → `NULL`，布尔 → `TRUE`/`FALSE`，对象/数组 → 紧凑 JSON 字符串，字符串按方言转义。
    - 输出：`INSERT INTO <表> (<列...>) VALUES (<值...>);`，单行语句，末尾分号；不包含事务。
  - **UPDATE**：
    - SET：全部 `!primaryKey && !autoIncrement` 的列，`col = sqlLiteral(value, driver)`；即使值未变化也写入，保证复制出的 UPDATE 能还原该行。
    - WHERE：全部主键列；值非 NULL 用 `col = <literal>`，值为 NULL 用 `col IS NULL`；复合主键用 `AND` 连接。
    - 表无主键时 UPDATE 项禁用，子菜单显示「无主键，无法生成 UPDATE」；有主键但没有可更新列时禁用并提示「没有可更新的非主键字段」。
    - 输出建议多行，便于阅读：`UPDATE <表>\nSET\n  col1 = ...,\n  col2 = ...\nWHERE pk = ...;`，末尾分号。
  - **JSON**：全部列，单个对象，`JSON.stringify(object, null, 2)`；键按 `columns` 顺序；包含自增主键（JSON 是行快照，不是可重复插入的语句）。
  - **列/行来源**：使用 `rows.value[rowIndex]` 与 `columns.value`；排序/筛选后的行就是屏幕行，行号无需换算。
  - **状态**：`loading` 或 `saving` 时禁用「复制为」子菜单，避免复制旧页/保存中的行。
  - **驱动/转义复用**：删除本地 `quoteIdentifier`；`conditionFor()` 改用 `quoteIdentifier()` + `sqlLiteral()`（NULL 仍走 `IS NULL`）。`driver` 为可选 prop，统一用 `props.driver ?? "sqlite"` 兜底。
- **查询结果网格（ResultGrid）实现细节**：
  - **入口**：单元格右键菜单在「复制整行」之后增加直接项「复制为 JSON」（不建子菜单，因为只有一个动作）。表头菜单不增加行级复制。
  - **取值**：`const row = sortedRows.value[cellMenu.rowIndex]`；值 = `visibleColumns.value.map(column => row[column.index])`；键 = `visibleColumns.value.map(column => column.name)`。因此当前排序和隐藏列状态会被正确尊重。
  - **JSON**：单个对象、2 空格缩进、无尾随换行；嵌套对象/数组保持；NULL 为 `null`。
  - **列名校验**：调用 `columnNameIssue(visibleColumns.value.map(c => c.name))`；非空时禁用「复制为 JSON」，菜单底部显示具体原因（空列名/重复列名），不静默覆盖键。
  - **无表名/无主键**：不提供 INSERT/UPDATE；不生成占位表名，避免用户误执行。需要整结果 SQL 时使用 B-02 的「导出… → SQL INSERT」并填写目标表名。
  - **隐藏列提示**：`hiddenCount > 0` 时成功提示为「已复制 JSON（仅可见列，已隐藏 N 列）」；否则「已复制 JSON」。
  - **只读连接**：JSON 复制不受影响；复制动作不写库、不写执行历史。
- **共用 `sql-literal.ts` 的复用要求**：
  - 新增 `src/lib/row-copy.ts`，只放纯函数，不 import Vue：

  6. 执行历史记录本次查询为失败/取消状态，并保留已耗时；不写入「成功」。
  7. 只取消目标查询，不关闭连接、不回滚用户手动事务以外的状态；若查询处于手动事务中，取消后事务仍可继续提交/回滚。
- **验收标准**：
  - [ ] MySQL 执行 `SELECT SLEEP(30)`，点击「停止」后 2 秒内返回「已取消」，随后执行 `SELECT 1` 成功。
  - [ ] PostgreSQL 执行 `SELECT pg_sleep(30)`，点击「停止」后 2 秒内返回「已取消」，连接仍可用。
  - [ ] SQLite 执行长递归 CTE，点击「停止」后能结束等待；若只能靠 60 秒超时，则必须显示超时提示且后续查询可用。
  - [ ] 查询超时 60 秒后标签恢复可操作，没有残留运行状态；执行历史不是成功记录。
  - [ ] 两个查询标签同时运行，取消其中一个不会影响另一个。
  - [ ] 取消按钮在查询结束后消失，重复点击不会报错。
- **风险 / 备注**：SQLite 的取消能力受 `sqlx`/`sqlite3_interrupt` 支持限制，允许以超时兜底，但必须保证连接池不被永久占用；MySQL DDL 等隐式提交语句取消后可能已生效，需要提示用户自行确认。

### B-15 危险 SQL 二次确认

- **优先级**：P2
- **状态**：待办

- **用户问题 / 场景**：对象右键只能导出单张表/视图的 DDL；迁移或交接时需要整个库/模式的结构脚本，只能逐个对象复制再拼接，顺序和依赖容易出错。

  6. 导出的脚本在空库/空模式中可执行（MySQL `DEFINER` 去除或提示；PostgreSQL 模式名需可替换或使用当前 search_path）。
- **验收标准**：

  - [ ] 导出文件只有 DDL，不包含 INSERT 数据行。
- **风险 / 备注**：跨对象依赖（视图依赖视图、函数依赖类型）无法完全排序，失败对象需在汇总中说明；本项不替代数据库原生 `mysqldump`/`pg_dump`。

### B-22 Redis TLS 与 SSH 隧道

  - [ ] 通过 SSH 隧道连接内网 Redis，键扫描、键详情、命令控制台可用。
  - [ ] SSH 主机密钥变化时拒绝连接；首次连接 TOFU 行为与 MySQL/PG 一致。
  - [ ] TLS/SSH 下切换逻辑库与 Cluster 检测仍正确。
- **实现备注（2026-11-24）**：`redis_client::connect` 接受隧道后的 host/port，按 `ssl_mode=required` 使用 `TcpTls`（`redis` crate `tokio-rustls-comp` + `tls-rustls-webpki-roots`）；`AppState.redis_tunnels` 与缓存连接同生命周期，关闭 / 编辑 / 删除连接、切换只读时释放；连接测试通过 `connection_target` 复用 SSH 逻辑。当前只校验受信任根证书与主机名，自签 CA、客户端证书、跳过校验尚未实现；真实 TLS / SSH Redis 实例回归待做。
- **风险 / 备注**：Redis TLS 需要确认 `redis` crate 的 TLS feature 与打包体积；SSH 隧道复用 `ssh.rs`，但 Redis 连接建立时机与 SQL 驱动不同，需单独处理连接缓存失效。

### B-33 对象创建补全：视图 / 存储过程 / 函数 / 触发器

- **优先级**：P1
- **状态**：待办
- **范围**：前端（对象树 `+` / 工具栏「新建表」下拉、创建对话框、DDL 预览）；后端（复用 `execute_query`，必要时新增 DDL 模板/校验、MySQL DELIMITER 处理）；驱动（MySQL / PostgreSQL / SQLite）。
- **用户问题 / 场景**：Navicat 的对象创建是一级能力；mydb 目前只能建表，视图/存储过程/函数/触发器只能先手写 DDL 再执行，且 MySQL 触发器/过程的 `DELIMITER` 容易出错。
- **期望行为**：
  1. 「新建表」按钮变为拆分按钮：主点击仍然新建表，右侧 chevron 打开菜单：新建表、新建视图、新建存储过程、新建函数、新建触发器（按驱动显示/禁用）。
  2. 每种对象打开专用对话框：名称、目标库/模式、定义体（带 SQL 高亮/缩进）、可选 `OR REPLACE`/`DEFINER`/触发时机等；底部实时 DDL 预览。
  3. 创建前校验名称与必填项；执行后刷新对象树并打开对应对象（视图打开数据/结构，其余显示在对象分类）。
  4. MySQL 存储过程/函数/触发器使用 DELIMITER 包裹或由后端按单条构建执行，避免客户端分句；失败时不留下半成品对象。
  5. PostgreSQL 视图/函数/过程支持 `CREATE OR REPLACE`；触发器按表创建；SQLite 仅支持视图与触发器（不提供存储过程/函数）。
  6. 只读连接、Redis 连接禁用创建入口；错误显示数据库原始信息，保留对话框内容。
- **验收标准**：
  - [ ] MySQL/PostgreSQL 创建视图后对象树出现该视图，数据/结构可打开；`CREATE OR REPLACE` 选项生效。
  - [ ] MySQL 创建带 `BEGIN ... END` 的存储过程/函数成功，不因分号被误切；创建触发器成功并可在表结构/对象树看到。
  - [ ] PostgreSQL 创建函数（含参数/返回类型）和触发器成功；SQLite 创建视图/触发器成功，菜单不出现存储过程/函数。
  - [ ] 定义体语法错误时显示数据库错误，对话框不关闭、不创建对象；只读连接入口禁用。
  - [ ] 创建后对象树刷新，无需重启；工具栏/对象树两条入口使用同一对话框。
- **风险 / 备注**：MySQL `DEFINER` 与权限、PostgreSQL 函数重载/参数签名、SQLite 触发器 `WHEN` 语法差异需要按驱动模板处理；第一版可只提供“名称 + 定义体 + 预览”，高级选项后续补。

### B-34 备份与还原

- **用户问题 / 场景**：Navicat 提供备份/还原；mydb 现在只能逐对象导出 DDL/数据，恢复整个库需要手工拼文件。

- **风险 / 备注**：大数据量/二进制/权限/属主/序列当前值无法完全还原；需在 UI 明确“逻辑备份，不替代原生 dump”。

## 暂不纳入本批（长期探索）

以下方向不属于「轻量客户端」的近期范围，需要单独做架构评估，不占用本批 backlog 排期：

- **国产数据库 JDBC 桥接（达梦 / 金仓 / 神通）**：需要 JVM 运行时或独立 sidecar、JDBC 驱动分发与授权、跨平台打包，和当前纯 Rust 驱动的轻量路线冲突。建议先产出可行性方案（进程边界、驱动加载、连接池、打包体积、分发许可），再决定是否立项。
- **AI 助手 / MCP**：涉及外部模型服务、隐私与凭据管理，暂不纳入本地客户端核心。
- **跨窗口共享事务 / 驱动缓存**：分屏已在 B-29；真正的多窗口状态同步、跨窗口事务与连接缓存属于后续架构评估，不在本批。
- **国产数据库驱动适配细节**：方言、类型映射、分页与 DDL 差异需要独立调研，不随本轮主界面功能混做。
- **查询构建器 / 模型设计 / 数据生成**：属于 IDE 级能力，和当前轻量客户端定位冲突；如要做，先单独评估交互、画布/依赖和打包体积，不放进工具栏第一版。
